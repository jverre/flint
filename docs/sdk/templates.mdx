title: "Templates"
description: "Boot sandboxes from your own container images."
---

By default, sandboxes boot a minimal Alpine Linux rootfs. To give them your runtime, packages and tools, import a container image as a template. Sandboxes created from it start just as fast as from the default one.

Build and push the image with the tooling you already use (Docker, CI, a registry), then import it once. Importing a template needs an **admin** token; any token can boot the templates its tenant can see.

## Importing an image

<Tabs>
  <Tab title="Python SDK">
    ```python
    from flint import Sandbox, Template

    t = Template.import_image("python", "python:3.12-slim")
    print(t.digest)  # sha256:... the exact image the template holds

    sandbox = Sandbox(template_id=t.template_id)
    print(sandbox.commands.run("python3 --version").stdout)
    ```

    `import_image` blocks until the template is ready and raises if the import fails, with the reason.

    <ParamField path="name" type="str" required>
      The template's name; its ID is derived from it. Importing to an existing name replaces that template once the new image is ready.
    </ParamField>

    <ParamField path="image" type="str" required>
      A container image reference: `python:3.12-slim`, `ghcr.io/acme/app:1.4`, or pinned with `@sha256:...`. Images must be `linux/amd64`.
    </ParamField>

    <ParamField path="rootfs_size_mb" type="int" default="2048">
      The template's disk in MiB, from 64 to 16384. The image must fit, with room left for what sandboxes write.
    </ParamField>

    <ParamField path="tenant" type="str">
      Only this tenant's sandboxes may boot the template. Without it, every tenant's can.
    </ParamField>

    <ParamField path="registry_auth" type="dict">
      `{"username": ..., "password": ...}` for a private registry. Flint uses it for this pull only and never stores it.
    </ParamField>
  </Tab>
  <Tab title="CLI">
    ```bash
    flint templates import python python:3.12-slim

    # A private registry: you are prompted for the password, or pipe it in
    echo "$GHCR_TOKEN" | flint templates import app ghcr.io/acme/app:1.4 \
      --registry-user acme-bot --registry-password-stdin --tenant acme
    ```
  </Tab>
  <Tab title="REST API">
    `POST /templates`

    ```bash
    curl -H "Authorization: Bearer $FLINT_API_KEY" -X POST http://localhost:9100/templates \
      -H "Content-Type: application/json" \
      -d '{"name": "python", "image": "python:3.12-slim"}'
    ```

    The import runs in the background. Poll `GET /templates/{template_id}` until `status` is `"ready"`. See the [API reference](/api-reference/templates) for every field.
  </Tab>
</Tabs>

## What Flint does with the image

- **Pins it.** A tag is resolved to its digest once, at import. The template never changes when the tag moves; import again to update it.
- **Keeps its environment.** The image's `ENV` (including `PATH`) applies to every command run in the sandbox, as with `docker run`. `ENTRYPOINT` and `CMD` don't run: sandboxes run what you send them.
- **Adds Flint's guest agent** and a small static toolset used at boot, so minimal and distroless images work. If the image has no `/bin/sh`, the bundled one stands in.
- **Never runs the image outside a VM.** The image is pulled and turned into a disk inside a disposable, jailed builder VM; its code first runs when the template's golden snapshot is taken, in a jailed VM like any sandbox.

## Listing and deleting

```python
for t in Template.list():
    print(t.template_id, t.status, t.image)

Template.get("python").delete()  # admin only; running sandboxes keep running
```

```bash
flint templates list
flint templates delete python
```

You can't delete the `default` template.

## How long an import takes

Pulling and converting depends on the image size: typically 20 seconds to a few minutes. After that, `Sandbox(template_id=...)` restores the template's snapshot and is as fast as the default template.
