The `flint` CLI groups commands under daemon control, backend selection, and agent deployment. Most of the time you'll just need `flint start` to get the daemon running and `flint app` to open the TUI.

## Core commands

| Command | Description |
|---------|-------------|
| [`flint start`](/cli/start) | Start the daemon (`--backend`, `--port`, `--data-dir`, `--state-dir`) |
| [`flint app`](/cli/app) | Open the interactive TUI |
| [`flint list`](/cli/list) | List running sandboxes |
| [`flint stop <vm_id>`](/cli/stop) | Kill a sandbox |

## Access

| Command | Description |
|---------|-------------|
| `flint ui` | Open the web UI signed in with the daemon's admin token (`--no-open` prints the link) |
| `flint login` / `flint logout` | Sign in to the server at `FLINT_URL` with its identity provider ([SSO](/sso)) |
| `flint token create` | Create an API token for TCP clients (`--kind service\|admin`, `--tenant`, `--name`); printed once |
| `flint token list` | List tokens, never their secrets |
| `flint token revoke <id>` | Revoke a token |
| `flint events` | Stored events (`--vm`, `--tenant`, `--type`, `-f` to follow, `-o json`) |
| `flint audit` | The audit log; `--verify` checks its hash chain |
| `flint quota set <tenant>` | Limit a tenant's VMs, vCPUs, memory and volume space (`--max-vms`, `--max-vcpus`, `--max-memory-mib`, `--max-volume-gib`) |
| `flint quota show <tenant>` | A tenant's limits and use |

The CLI talks to the daemon over its Unix socket, so it needs the daemon's user (for example `sudo`) or the `flint` group. Set `FLINT_URL` and `FLINT_API_KEY` to use TCP instead. See [Connecting](/api-reference/overview#connecting).

## Templates

Importing and deleting need an admin (the daemon's socket is one). See [Templates](/sdk/templates).

| Command | Description |
|---------|-------------|
| `flint templates list` | List templates, their status and image |
| `flint templates import <name> <image>` | Import a container image as a template; `--tenant`, `--disk`, `--registry-user` |
| `flint templates delete <name>` | Delete a template; running sandboxes keep running |

## Backends

| Command | Description |
|---------|-------------|
| [`flint backends list`](/cli/backends) | List installed backends and their preflight status |

## Host setup

| Command | Description |
|---------|-------------|
| `flint install-deps` | Install Firecracker, jailer, and vmlinux kernel (Linux); `--backend cloud-hypervisor` installs Cloud-Hypervisor instead |
| `flint install-deps --check` | Verify installed dependencies |
| `flint setup-macos` | Prepare macOS Virtualization.framework guest assets |
| `flint setup-macos --check` | Verify macOS guest assets |

## Configuration

The daemon reads configuration from environment variables:

| Variable | Default | Description |
|----------|---------|-------------|
| `FLINT_PORT` | `9100` | Port the daemon listens on |
| `FLINT_DATA_DIR` | `/var/lib/flint/data` (Linux), `~/Library/Application Support/flint/data` (macOS) | Where VM rootfs images and snapshots are stored |
| `FLINT_STATE_DIR` | `/var/lib/flint/state` (Linux), `~/Library/Application Support/flint/state` (macOS) | Where the daemon keeps its state (SQLite db, pid file, logs) |
| `FLINT_BACKEND` | host default | Backend plugin to use (`firecracker`, `cloud-hypervisor`, `macos-vz`) |

```bash
FLINT_PORT=9200 FLINT_BACKEND=cloud-hypervisor flint start
```
